# SENSANIN v2.5 — Supplied Label Correction

This is an incremental patch over SENSANIN v2.4. No visual redesign. The original v2.3 autoScan.ts and original label artwork are preserved.

## Entity identities
- Batch ID: internally generated at receiving; e.g. B-20261124-001.
- Package ID: internally generated, one per product package; e.g. SN-000001.
- Label ID: issued on the physical prefabricated SENSANIN label, entered by staff on receipt; e.g. LBL-SN-0001. Not generated by the supermarket.

## Operation sequence
1. Record existing supplied Label IDs in Penerimaan / Stok Label Fisik (bulk input).
2. Register beef batch; generates independent Package IDs and batch identity.
3. In that batch, Pasangkan Label links AVAILABLE physical Label IDs to packages. Each label and package can have at most one active association.
4. Place products via dropdowns (Chiller/Rack/Level), independent of label assignment.
5. Scan the prefabricated label; decoded QR must match a Label ID in supplied stock, assigned to an existing Package ID. Successful scan updates package status and marks label USED; subsequent scans still work.
6. Damage/invalidation is logged, and an unused replacement Label ID can be associated with the same Package ID.

## Label statuses
- AVAILABLE: recorded from supplied stock, not associated.
- ASSIGNED: associated with a package.
- USED: scanned at least once.
- DAMAGED: unusable, never associated or scanned again; a replacement can be assigned to the package.

## What changed
- Removed QR generation, QR download and sticker printing from Receiving UI.
- Added physical label stock list, bulk ID recording, linking and invalidation.
- Scanner now resolves Label ID → Package ID, with no fallback to treating a Package ID as a Label ID.
- Activity has Label Intake, Label Assignment, and Label Invalidated events.
- Data Inventory and product details show assigned Label ID.
- Existing five-item navigation, UI theme, location handling and autoScan.ts retained.

## Important limits
- The prior v2.4 LocalStorage data is retained, but its packages have no invented label bindings. They must be paired with supplied label IDs before scanning.
- No actual camera tests or complete npm build were possible in this environment. Run `npm install && npm run build` locally; test in browser before deployment.
- A physical Color QR must encode the true Label ID. If a supplied label encodes another payload format, adjust `resolveLabelQR` in `src/labelInventory.ts`.
- Front-end LocalStorage is single-device demo storage; backend + proper authentication would be required in production.
